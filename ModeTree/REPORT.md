# ModeTree-JAC — technical report

Multimodal compositional inference for COMPASS: a deterministic, branch-based
posterior reconstruction that keeps the GAUSS/JAC cost profile and fixes its
failure on multimodal global posteriors.

Companion documents: `TECHNICAL_NOTE.md` (Milestone 0 — what the existing
COMPASS code does, verified from source) and `artifacts/TABLES.md` (all numbers,
regenerated by `experiments/run_all.sh`). Figures are in `artifacts/figures/`.

---

## 1. What was built

```
modetree/
  benchmarks.py    Milestone A   Gaussian-mixture factor models with exact
                                 row posteriors, exact tall log density, and
                                 dense 1-D / 2-D grid references
  composition.py   Milestone B   the exact clean (t=0) compositional score,
                                 arrowhead curvature, Schur elimination,
                                 batched over all n rows
  refine.py        Milestone C   damped/trust-region Newton on S_0 = 0, plus a
                                 batched refiner for probe sets
  energy.py        D, E          composite Gauss-Legendre score line integration,
                                 multi-path estimates, cycle residuals,
                                 weighted graph-Laplacian reconciliation
  laplace.py       F, G          structured Laplace branch evidence, Laplace+
                                 with a basin guard, posterior assembly
  diffusion.py     L, M          diffusion-time composed fields (uncorrected /
                                 fnpe / gauss_jacobian) on oracle row scores,
                                 the reusable row_jacobian_factor, sparse JAC
  tree.py          H, I, J, K, N mode continuation, curvature spawning,
                                 sentinel probes, branch management, the
                                 switch to the clean composition
  samplers.py                    VE reverse SDE and annealed Langevin baselines
  runtime.py                     the repository's 3-thread CPU cap
src/compass/priors.py  section 3 prior-object interface for MultiObsSampler,
                                 with the exact diffused Gaussian-mixture score
```

`MultiObsSampler` itself is changed in exactly two places — `_resolve_prior`
gains an object branch and `_diffused_gaussian_prior_score` dispatches to it.
The `(mean, scale)` tuple path is untouched and is what every existing caller
still takes. **The score network is neither retrained nor altered**, and no
single-observation score is modified anywhere.

Tests: `python -m pytest ModeTree/tests -q` (101 tests).

## 2. Method

For each global branch `b`:

1. **Continuation.** Follow the root of the composed field `S_t` down the
   diffusion schedule with a predictor-corrector. New branches appear from
   curvature-triggered probes (the softest eigenvalue of the branch precision
   falling through zero) and from sentinel probes at a few checkpoints.
2. **Switch to the clean composition** below `switch_to_clean_t`, refine to
   `||S_0|| < 1e-11` on the exact composed score
   `S_0,g = s_prior + sum_i (s_i,g - s_prior)`, and run one final sentinel
   sweep against that clean field (see 3.4).
3. **Energies.** Reconstruct `E_b - E_a` by score line integration along several
   geometrically distinct paths, and reconcile the pairwise differences into
   globally consistent energies with a weighted graph-Laplacian least squares.
4. **Structured Laplace.** `P_g,b = A_b - sum_i B_ib C_ib^-1 B_ib^T`,
   `log|H_b| = log|P_g,b| + sum_i log|-C_ib|`, so
   `log Z_b = E_b - 1/2 log|H_b|` and `w_b = softmax(log Z_b)`.
5. **Laplace+** (optional) corrects the within-branch non-Gaussianity with a
   randomised-Sobol estimate of `C_b = E_{q_b}[exp(R_b)]`, restricted to the
   branch's own basin.

Cost is `O(n B)` per evaluation and `B` stays at the true mode count; nothing
anywhere forms the `prod_i K_i` mixture the task forbids.

## 3. Results

### 3.1 Section 25 — the gate: known modes, oracle clean score

Nine 1-D regimes × `n = 1, 2, 4, 8, 16, 32, 64, 100`
(`artifacts/experiment1_known_modes.json`, 72 cells):

| quantity | worst over all cells |
|---|---|
| final score norm `max ||S_0||` | `2.9e-11` (`tilt_2.0`, `n = 1`) |
| MAP error / posterior sd | `1.3e-9` (`narrow_broad`, `n = 64`) |
| energy-gap error (vs exact mode log heights) | `3.8e-13` (`empty_valley`, `n = 64`) |
| mode-weight TV (structured Laplace) | `0.020` (`narrow_broad`, `n = 1`); `< 5e-4` for `n >= 8` |
| mode-weight TV (Laplace+) | `0.006` (`narrow_broad`, `n = 1`); `< 1.2e-3` for `n >= 4` |
| minimum Laplace+ ESS fraction | `0.87` |

The gate passes decisively, so the discovery milestones were worth building.
Two findings from this stage were structural rather than cosmetic:

* **Quadrature must refine by panels, not by order.** Between two separated
  modes the integrand is `O(n * separation / s^2)` while the integral is `O(1)`.
  Raising the Gauss-Legendre order alone leaves a truncation error that grows
  linearly in `n` — 0.73 nats at `n = 100` on `empty_valley`, i.e. a mode-weight
  TV of 0.18 on a target whose two modes are *exactly* tied. Composite
  refinement by panel doubling, with the convergence test taken relative to
  `int |S . dtheta|` rather than to `|value|` (which is exactly zero for a
  symmetric pair), removes it entirely: `1.7e-13` at `n = 100`. On a fixed
  2-D path the panel ladder at `q = 16` goes `2.3e-1 -> 1.4e-4 -> 3.7e-8 ->
  7.9e-15`; the same ladder at `q = 4` stalls at `1.2e-5`.
* **Laplace+ needs a basin guard.** `C_b = E_{q_b}[exp(R_b)]` integrates over
  the whole space. When the branches are well separated that is the basin mass;
  when they are not, every branch's estimate converges on the *total* mass and
  the weights collapse toward uniform. On a deliberately skewed two-mode target
  at `n = 2`, plain Laplace gives weight TV 0.026 and **unguarded Laplace+
  gives 0.052** — worse than not correcting at all. Restricting the estimator to
  points whose path from the mode descends monotonically (a free test on scores
  already being integrated) gives 0.0009. The gate table's
  `TV (Laplace+, no guard)` column shows the same effect at `n = 1` across
  regimes: e.g. 0.051 unguarded against 3.6e-4 guarded on `tilt_2.0`.

### 3.2 The headline comparison

Oracle row scores throughout, so this compares composition rules and inference
procedures, not score networks (`artifacts/TABLES.md`). At `n = 100`, W1 to the
exact tall posterior — for ModeTree this is the analytic W1 of the returned
Gaussian mixture, which is what the method actually produces:

| case | uncorrected | gauss_jacobian | F-NPSE | ModeTree+ |
|---|---|---|---|---|
| symmetric | 0.053 | 0.0075 | 0.381 | **1.3e-4** |
| nearly_tied | 0.609 | 0.492 | 0.682 | **1.3e-4** |
| map_vs_mass | 10.6 | 1.259 | 1.306 | **5.2e-5** |
| narrow_broad | 3.99 | 2.546 | 2.544 | **1.3e-4** |
| empty_valley | 15.0 | 0.081 | 0.106 | **4.4e-8** |
| vanishing | 2.11 | 0.736 | 0.712 | **3.4e-4** |

and mode-weight total variation:

| case | gauss_jacobian | F-NPSE | ModeTree+ |
|---|---|---|---|
| map_vs_mass | 0.313 | 0.339 | **8.2e-6** |
| nearly_tied | 0.123 | 0.126 | **3.5e-6** |
| empty_valley | 0.0080 | 0.0090 | **4.2e-14** |

Missing posterior mass is zero on every 1-D regime at every `n >= 2`; the sole
exception in 48 discovery cells is `narrow_broad` at `n = 1`.
`uncorrected` diverges outright at large `n` on the asymmetric targets
(`e_MAP/sd` of 33 and 87 on `map_vs_mass` and `narrow_broad` at `n = 100`).

The comparison also reports a sampled W1 from 2000 draws so the ModeTree row is
like-for-like with the samplers; that number has a Monte-Carlo floor of about
`sd / sqrt(2000) ~ 0.045`, which at `n >= 8` is *larger* than the method's own
error, so the analytic column is the informative one.

### 3.3 Where the errors come from

The error ladder (section 11 of the brief) is implemented as
`modetree_known` / `modetree` / the perturbed-score study:

| rung | isolates | result |
|---|---|---|
| known modes + oracle score | energy integration, Laplace, Laplace+ | machine precision; weight TV `< 5e-4` for `n >= 8` |
| oracle score + discovery | mode discovery | identical to the known-mode rung on every 1-D regime and every `n >= 2`; the single discovery failure in the whole 1-D study is `narrow_broad` at `n = 1`, where the secondary mode is shallow and no bifurcation announces it (0.60 of the mass missed) |
| perturbed row scores | network bias | see below |

Injected row-score error (`artifacts/score_error_scaling.json`), fitted
`error ~ n^alpha` on `n = 1 ... 256`:

| shape | alpha | `e_MAP` at n=100 (bias 0.01) | weight TV at n=100 |
|---|---|---|---|
| systematic (fixed direction) | **+1.000** | 0.010 | **0.367** |
| zero-mean i.i.d. per row (8 draws) | **+0.492** | 2.0e-4 | 0.019 |
| systematic state-dependent | +1.000 | 0.0097 | 0.000 |

This is the most consequential number in the study. A systematic
per-observation score bias accumulates exactly as `O(n)`, and its effect on the
**MAP** is benign — the error stays of order the bias in parameter units, the
behaviour the `MultiObsSampler` docstring already describes. Its effect on
**mode weights** is not: a 0.01 bias produces a weight TV of 0.37 at `n = 100`,
because a mode weight depends on the log-density *difference* between modes and
that difference accumulates linearly while the posterior contracts. Zero-mean
error behaves as `sqrt(n)` and is comparatively harmless.

The practical consequence: **at large `n`, ModeTree-JAC's mode weights will be
limited by the network's systematic bias, not by anything in the reconstruction
chain.** Mode *locations* and the MAP are far more robust.

### 3.4 Mode discovery, and what is load-bearing

`artifacts/experiment_2d.json` runs each 2-D regime with both mechanisms, with
sentinels only, and with curvature spawning only.

* **Sentinel probes are necessary; curvature spawning alone is not sufficient.**
  In two dimensions curvature-only discovery recovers 0–50% of the modes on
  every four-mode target (0% on the symmetric one, where the branch sits on a
  saddle whose single softest direction points at none of the corners) while
  sentinels alone match the full method.
* The `remote_small` regime — a 10% mode at `(4.2, 3.4)` that no bifurcation of
  the dominant central mode reaches — is found at every `n` with sentinels and
  never without (missing mass 0.098). This is exactly what section 15 was
  designed to test.
  Across the twenty 2-D cells: with sentinels (alone or with curvature) mean
  mode recall is 1.00, missing mass 0.000 and the worst weight TV 0.003; with
  curvature spawning alone mean recall is 0.36 and mean missing mass 0.48.
* In one dimension the two mechanisms are complementary: `symmetric` and
  `empty_valley` bifurcate and are found by curvature; `map_vs_mass` and
  `narrow_broad` never bifurcate (the continuation slides into one basin) and
  are found only by sentinels. The full ablation at `n = 100`
  (`artifacts/ablations.json`) makes the point sharply -- `no_sentinel` is the
  **only** variant that breaks anything:

  | case | variant | recall | missing mass | e_MAP/sd |
  |---|---|---|---|---|
  | map_vs_mass | full | 1.00 | 0.000 | 1.4e-10 |
  | map_vs_mass | no_sentinel | 0.50 | 0.339 | **2.11** |
  | empty_valley | no_sentinel | 0.50 | 0.500 | 5.5e-13 |
  | narrow_broad | no_sentinel | 0.00 | 1.000 | **87.1** |

  every other variant (`no_curvature`, `one_path`, `stride2/4/8`, both switch
  times, `tangent`) is bit-identical in accuracy to `full`.

Five implementation facts decided whether discovery works at all. Each is
recorded as a comment at the point of use, because each looked like a tuning
detail and was actually a correctness bug:

1. The probe distance must come from the branch's **pre-bifurcation** width. The
   obvious `1/sqrt(|lambda_min|)` *shrinks* as the split deepens, so every probe
   falls back into the saddle; with that choice the symmetric benchmark ends
   with **zero** branches at `n = 100`.
2. Probe acceptance must be a precision-weighted residual `sqrt(s^T P^-1 s)`,
   not `||S||`. At `n = 100` the curvature is several hundred, so a root located
   to `1e-4` in position still shows `||S|| ~ 1e-2`, and a fixed
   `||S|| < 1e-4` test rejects genuine modes systematically.
3. Probe results must be collapsed **among themselves** before reaching the
   branch list, or `max_branches` fills with near-duplicates of the branch that
   already exists and the genuinely new mode never gets a slot.
4. A **saddle must never be a merge target.** A saddle has no basin, so
   "duplicate of the saddle" is not a meaningful claim; with a generous
   Mahalanobis tolerance it swallows the very branches it just spawned. At
   `n = 1`, where the two modes sit only ~1.8 local standard deviations from the
   origin, this returned *zero* branches.
5. **A mode of width `w` is invisible in the `lambda`-smoothed field above
   `lambda ~ w`,** so a narrow mode can be absent at every diffusion-time
   checkpoint and still be a genuine maximum of the target. In 2-D
   `narrow_broad` at `n >= 64` the narrow mode has posterior width `~0.05`
   while the last checkpoint sits at `lambda ~ 0.4`: the continuation misses the
   MAP branch and 36% of the mass. One final sentinel sweep against the
   **clean** field — one batched refinement — repairs it, and has no such blind
   spot by construction. This is the `final_clean_sentinels` default.

The mode-equivalence metric is the spectral absolute value of the precision, not
the raw quadratic form, which is indefinite at a saddle.

**Milestones M and N, answered by the same ablation.** Sparse JAC is free:
`jacobian_stride = 8` cuts Jacobian evaluations by 2.2x (2578 -> 1193 on
`map_vs_mass` at `n = 100`) at *zero* accuracy cost, and saves ~15% wall clock.
The switch time barely matters over two decades (`t = 0.05` to `t = 0.002`
change nothing but the Jacobian count). And the sophisticated tangent predictor
of Milestone H is **not worth keeping**: it costs more Jacobian evaluations
(2688 vs 2578) and more wall clock (11.2 s vs 9.4 s on `empty_valley`) than the
trivial carry-over predictor, for no accuracy gain anywhere. The default stays
`predictor="carry"`, as the brief asked be determined by measurement.

Multi-path integration and cycle consistency are likewise free of accuracy
*benefit* on the oracle field (`one_path` matches `full` exactly), which is the
expected result for a conservative field -- their value is as instrumentation
for the learned-score case, where the field is not conservative.

### 3.5 Sections 13–17: the special tests

* **MAP vs mode mass (13).** `map_vs_mass` is constructed so the higher peak and
  the heavier mode are different branches at *every* `n` (peak at `+mu`, 66% of
  the mass at `-mu`). ModeTree reports them separately and correctly; a test
  asserts `map_index != mass_index`. The 2-D `narrow_broad` regime is the same
  test in two dimensions and the 2-D `unequal_covariance` regime is its purest
  form: four modes with *exactly tied* heights whose masses differ only through
  their volumes.
* **Empty valley (14).** With two modes separated by an essentially zero-density
  region ModeTree places no branch in the valley (asserted: every branch has
  `|g| > 4`) and recovers the exactly-tied energies to `1.7e-13` at `n = 100`,
  giving a W1 of `4.4e-8` where `gauss_jacobian` gives `0.081`.
* **Remote small mode (15).** See 3.4.
* **Mode disappearance with `n` (16).** The `vanishing` and `narrow_broad`
  regimes carry a fixed per-observation tilt, so one mode dies exponentially.
  ModeTree keeps it while it has mass, lets its weight shrink, and the branch
  count follows the truth rather than a constant — at `n = 100` on
  `narrow_broad` it still reports the second branch, now with negligible weight.
* **Very close mode heights (17).** `nearly_tied` keeps the two modes within a
  few `1e-2` of each other at all `n`; the reconstructed energy-gap error stays
  below `2.3e-13`, so the evidence auditor never fires. Multi-path disagreement,
  reverse-path residuals and cycle residuals are computed and stored regardless
  and sit at `~1e-14` for the oracle field — which is the point: they are the
  quantities that become informative with a learned, non-conservative score.

### 3.6 Calibration

SBC on 191 simulated datasets at `n = 16` (`artifacts/calibration.json`,
figure 6): mean rank 0.524 (uniform: 0.5), rank sd 0.301 (uniform: 0.289).
Empirical coverage against nominal:

| nominal | 50% | 80% | 90% | 95% |
|---|---|---|---|---|
| empirical | 0.429 | 0.817 | 0.921 | 0.932 |

with a standard error of about 0.036. Coverage is close to nominal at the 80%
and 90% levels and modestly low (about 2 se) at 50%. This is the weakest

### 3.7 Hierarchical models, including the COMPASS shape

`artifacts/experiment_hierarchical.json` runs `d_g x d_l` of `1x1`, `2x1` and
`7x3` (the COMPASS shape) at `n = 1, 4, 16, 64, 100`. Discovery recovers both
true global modes at every shape and every `n` (`recall = 1.00`, `B = 2/2`),
with the full arrowhead Schur path exercised throughout. At `d_g = 1`, where an
exact global-marginal reference is available, ModeTree's W1 is 0.007–0.09
against 0.08–0.24 for `gauss_jacobian` and 0.16–0.50 for F-NPSE. At `d_g = 2`
and `7` only mode recovery and runtime are reported: a distributional metric
would need a `d_g`-dimensional reference, which the grid construction does not
provide above one dimension.

### 3.8 Benchmark construction (a result in its own right)

For a product of `n` identical factors the tall log-height gap between two modes
is `n` times the per-factor gap. **Any** fixed per-observation asymmetry
therefore kills all but one mode exponentially — at `n = 100`, a 0.62/0.38
component weight leaves the second mode with `6e-22` of the mass. A benchmark
whose mode weights stay non-degenerate along the `n` ladder must calibrate the
per-observation tilt as `O(1/n)`, and in `d > 1` must calibrate the **volume**
term `-1/2 log|S_k|` too, since that is multiplied by `n` as well. Both
calibrations are implemented (`tilted_two_mode_1d`,
`calibrate_component_weights`) and both kinds of regime are kept: the calibrated
ones probe weight accuracy at high `n`, the fixed-tilt ones probe mode
disappearance.

A second, smaller construction finding: the 2-D basin-mass reference needs local
maxima to be **fixed points** of the steepest-ascent map. Without that the
pointer-doubling walk leaves every basin and a four-fold symmetric target
reports masses of 0.625/0.125/0.125/0.125 instead of 0.25 each — a reference
error that would have been read as a method error.

## 4. Answers to the ten research questions

**Q1 — can curvature continuation + sparse sentinels recover all meaningful
modes?** Yes on every benchmark here, but *only with sentinels*, and only with
the final clean sweep of 3.4 item 5. Curvature spawning alone fails on every
target whose second mode is born by a saddle-node rather than a pitchfork:
all the 2-D four-mode targets and the 1-D `map_vs_mass` / `narrow_broad`
regimes.

**Q2 — can score-line integration + cycle consistency recover relative mode
heights?** Yes, to `2.3e-13` on the oracle field at `n = 100` — but only with
panel-refined composite quadrature. With order-only refinement the error grows
linearly in `n` and reaches 0.73 nats.

**Q3 — does structured Laplace recover relative mode masses as `n` grows?**
Yes, and it *improves* with `n`: weight TV falls from ~0.02 at `n = 1` to
`< 5e-4` by `n = 8` and `< 1e-4` by `n = 32`, because the modes narrow relative
to their separation.

**Q4 — does Laplace+ materially improve on ordinary Laplace?** At small `n`,
substantially: 0.043 → 0.0005 weight TV on a skewed target at `n = 1`, and
0.020 → 0.006 on `narrow_broad` at `n = 1`. At large `n` the improvement is real
but immaterial because plain Laplace is already at `1e-5`. Its ESS never
collapsed (minimum observed fraction 0.87).

**Q5 — at what `n` does Laplace+ become unnecessary?** Around `n = 8`–`32` for
these targets. Beyond `n ~ 32` the two agree to better than the Monte-Carlo
resolution of any downstream use, and at a few cells Laplace+ is marginally
*worse* because its QMC error (`~1e-6`) then exceeds the Laplace error it is
correcting.

**Q6 — how does learned score bias accumulate with `n`?** `alpha = 1.000` for
systematic error and `alpha = 0.492` for zero-mean error, exactly as the algebra
predicts. The damage lands on mode weights, not on the MAP. See 3.3.

**Q7 — does ModeTree-JAC improve with `n`?** Every component of the
reconstruction improves with `n`: the modes narrow, Laplace gets better, the
energies stay exact, and the W1 falls monotonically. With a *learned* score the
systematic-bias term of Q6 will eventually dominate the weights; on present
evidence the crossover is at a bias of order `0.005–0.01` in score units.

**Q8 — discovery or weighting as the remaining error source?** With oracle
scores, neither: both reach machine precision once the five implementation facts
of 3.4 are right. With a biased score, **weighting**, by a wide margin.

**Q9 — how many branches?** The true mode count, plus transient saddle branches
that are pruned. `B <= 4` on every benchmark here and the branch count does not
grow with `n`, so failure condition 6 is not triggered.

**Q10 — is it faster than F-NPSE?** **Yes, and by more than the target.** On an
uncontended machine (`artifacts/timing.json`, best of three, 2000 draws,
`map_vs_mass`):

| n | gauss_jacobian | F-NPSE | ModeTree (total) | ModeTree / F-NPSE |
|---|---|---|---|---|
| 8 | 2.07 s | 3.94 s | 1.37 s | **0.35** |
| 32 | 7.28 s | 15.93 s | 2.43 s | **0.15** |
| 100 | 22.68 s | 46.36 s | 4.50 s | **0.097** |

The target `T_ModeTree < 0.5 T_FNPSE` is met from `n = 8` upward, and ModeTree
is also 5x faster than `gauss_jacobian` reverse diffusion at `n = 100`. The
reason is structural: the samplers carry 2000 particles through 200 (or
100 x 10) levels, while ModeTree carries `B` branches and then *returns a
density* rather than draws. The split at `n = 100` is 4.22 s discovery +
0.28 s energies and Laplace+ + ~0 s sampling. Caveat in 5.2.

## 5. Honest accounting

### 5.1 What is not done

* **The learned-network rung (section 27) is not run.** Everything is built and
  tested against *oracle* row scores. Running it requires a trained COMPASS
  checkpoint on a multimodal tall-data model; the adapters it needs are the ones
  `TECHNICAL_NOTE.md` section 4.1 identifies (`_raw_row_scores`,
  `_row_score_jacobian`), and `row_jacobian_factor` already takes a network
  Jacobian unchanged. Until that is run, no claim here about network error is
  empirical except the injected-error study of 3.3, which is a controlled proxy
  and is labelled as one.
* **SBC is run at one `(case, n)` only**, on a synthetic bimodal target, with
  191 datasets and 200 draws each — resolution about ±0.036 on coverage. It is
  not enough to compare ModeTree's calibration against F-NPSE's, which is what
  failure condition 3 asks for.
* **Laplace+ for hierarchical models** is not implemented; it is defined on the
  global block, and the hierarchical path uses ordinary structured Laplace. The
  profiled-composer route is sketched in `laplace._global_score`, not built.
* **Milestone O (the evidence auditor)** exists only as the diagnostics it needs
  — per-pair `sigma_ab`, multi-path disagreement, reverse residuals and cycle
  residuals are all computed and stored — but the *escalation* (more quadrature,
  more paths, PF-ODE log density) never triggers on the oracle field because the
  disagreement is at machine precision. It is the right piece to build with the
  learned network, not before.
* **Milestone M4 (low-rank JAC)** was deliberately not built: profiling does not
  show Jacobian cost dominating at these dimensions, and the brief says not to
  add the machinery unless it does.
* **No `d_g > 1` distributional metric.** At `d_g = 2` and `7` the hierarchical
  study reports mode recovery and runtime only.
* **The `mode_tree_jac` correction is not wired into `MultiObsSampler.sample`.**
  ModeTree is a standalone pipeline against the composed-field interface; the
  `correction=` string and the `ModeTreeConfig` plumbing into `sample()` are the
  natural next integration step and are deliberately not landed before the
  network rung.

### 5.2 Runtime, with the caveat attached

The timing table in Q10 is uncontended and repeated, and the ratios are sound
for *this* cost model: with an oracle score, one composed-field evaluation is
microseconds. With a transformer score network the per-evaluation cost rises by
three to four orders of magnitude, so the ratio that transfers is the
*evaluation count*, not the wall clock. There ModeTree is less favourable:
it uses 500–4300 composed-field evaluations against 200 for a 200-step reverse
diffusion and 1000 for F-NPSE — but each of its evaluations is on `B <= 4`
states rather than 2000, so per *network* forward pass it is two to three orders
of magnitude cheaper. Both columns are in `artifacts/TABLES.md`. The honest
summary is that ModeTree should remain far ahead with a real network, but that
is an inference from the cost model, not a measurement.

## 6. Recommendation

**Yes for the reconstruction half and the prior interface now; ModeTree
discovery behind a flag until the learned-network rung is run.**

1. The **structured-Laplace + score-line-integration reconstruction**
   (Milestones B–G) is sound, exact to machine precision on every oracle
   benchmark, and improves with `n`. It should land in COMPASS as a
   post-processing step that turns any set of refined modes into a weighted
   posterior, independently of where the modes came from —
   `newton_map_estimate` already produces exactly the arrowhead quantities it
   needs.
2. The **prior-object interface** (`compass.priors`) should land
   unconditionally. It is backward-compatible, small, and removes a real
   limitation: the composition subtracts `(n-1)` prior scores, so a
   Gaussian-only prior is an `n`-fold amplified modelling error on any
   multimodal problem.
3. **ModeTree discovery** works, is faster than both baselines, and is by orders
   of magnitude the most accurate method measured here — but it is also the part
   with the most moving parts, and five of its behaviours were silently wrong in
   ways that produced zero or one branch rather than an error. It should ship as
   `correction="mode_tree_jac"` with `return_diagnostics=True` encouraged, and
   should not become the default until it has run against a real COMPASS
   checkpoint.
4. The **next experiment** is the one thing that would change this
   recommendation: run the 3.3 ladder with real network scores, measure the
   systematic bias of a trained COMPASS model in score units, and compare it
   against the `0.005–0.01` threshold at which mode weights start to degrade. If
   the measured bias is below it, ModeTree-JAC is ready to be a main COMPASS
   inference method for multimodal tall data. If it is above it, the correct
   response is better training, not a different composition rule — because 3.3
   shows the composition mathematics is not what is failing.

Against the brief's priority order
(`posterior correctness > MAP accuracy > mode-mass accuracy > calibration >
runtime`): on the first three, with exact scores, ModeTree-JAC beats
`gauss_jacobian` and F-NPSE by three to five orders of magnitude and has no
regime here where it is worse. On runtime it is 10x faster than F-NPSE at
`n = 100`. On calibration the evidence is thin and that is the gap to close
next, together with the network rung.
