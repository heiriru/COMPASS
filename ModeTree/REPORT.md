# ModeTree-JAC — technical report

Multimodal compositional inference for COMPASS: a deterministic, branch-based
posterior reconstruction that keeps the GAUSS/JAC cost profile and fixes its
failure on multimodal global posteriors.

Companion documents: `TECHNICAL_NOTE.md` (Milestone 0 — what the existing
COMPASS code does, verified from source) and `artifacts/TABLES.md` (all numbers,
regenerated by `experiments/summarize.py`).

---

## 1. What was built

```
modetree/
  benchmarks.py    Milestone A   Gaussian-mixture factor models with exact
                                 row posteriors, exact tall log density, and
                                 dense 1-D / 2-D grid references
  composition.py   Milestone B   the exact clean (t=0) compositional score,
                                 arrowhead curvature, Schur elimination,
                                 batched over all n rows
  refine.py        Milestone C   damped/trust-region Newton on S_0 = 0, plus a
                                 batched refiner for probe sets
  energy.py        D, E          composite Gauss-Legendre score line integration,
                                 multi-path estimates, cycle residuals,
                                 weighted graph-Laplacian reconciliation
  laplace.py       F, G          structured Laplace branch evidence, Laplace+
                                 with a basin guard, posterior assembly
  diffusion.py     L, M          diffusion-time composed fields (uncorrected /
                                 fnpe / gauss_jacobian) on oracle row scores,
                                 the reusable row_jacobian_factor, sparse JAC
  tree.py          H, I, J, K, N mode continuation, curvature spawning,
                                 sentinel probes, branch management, the
                                 switch to the clean composition
  samplers.py                    VE reverse SDE and annealed Langevin baselines
  runtime.py                     the repository's 3-thread CPU cap
src/compass/priors.py  section 3 prior-object interface for MultiObsSampler,
                                 with the exact diffused Gaussian-mixture score
```

`MultiObsSampler` itself is changed in exactly two places — `_resolve_prior`
gains an object branch and `_diffused_gaussian_prior_score` dispatches to it.
The `(mean, scale)` tuple path is untouched and is what every existing caller
still takes. **The score network is neither retrained nor altered**, and no
single-observation score is modified anywhere.

Tests: `pytest ModeTree/tests`.

## 2. Method

For each global branch `b`:

1. **Continuation.** Follow the root of the composed field `S_t` down the
   diffusion schedule with a predictor-corrector. New branches appear from
   curvature-triggered probes (the softest eigenvalue of the branch precision
   falling through zero) and from sentinel probes at a few checkpoints.
2. **Switch to the clean composition** below `switch_to_clean_t`, and refine to
   `||S_0|| < 1e-11` on the exact composed score
   `S_0,g = s_prior + sum_i (s_i,g - s_prior)`.
3. **Energies.** Reconstruct `E_b - E_a` by score line integration along several
   geometrically distinct paths, and reconcile the pairwise differences into
   globally consistent energies with a weighted graph-Laplacian least squares.
4. **Structured Laplace.** `P_g,b = A_b - sum_i B_ib C_ib^-1 B_ib^T`,
   `log|H_b| = log|P_g,b| + sum_i log|-C_ib|`, so
   `log Z_b = E_b - 1/2 log|H_b|` and `w_b = softmax(log Z_b)`.
5. **Laplace+** (optional) corrects the within-branch non-Gaussianity with a
   randomised-Sobol estimate of `C_b = E_{q_b}[exp(R_b)]`, restricted to the
   branch's own basin.

Cost is `O(n B)` per evaluation and `B` stays at the true mode count; nothing
anywhere forms the `prod_i K_i` mixture the task forbids.

## 3. Results

### 3.1 Milestone 25 — the gate: known modes, oracle clean score

Nine 1-D regimes × `n = 1, 2, 4, 8, 16, 32, 64, 100`
(`artifacts/experiment1_known_modes.json`):

| quantity | worst over all 72 cells |
|---|---|
| final score norm `max ||S_0||` | `1.1e-12` |
| MAP error / posterior sd | `< 1.4e-9` |
| energy-gap error (vs exact mode log heights) | `< 2.3e-13` |
| mode-weight TV (structured Laplace) | `0.020` (at `n = 1`); `< 0.001` for `n >= 8` |
| mode-weight TV (Laplace+) | `0.006` (at `n = 1`); `< 0.001` for `n >= 4` |
| minimum Laplace+ ESS fraction | `0.87` |

The gate passes decisively, so the discovery milestones were worth building.
Two findings from this stage were structural rather than cosmetic:

* **Quadrature must refine by panels, not by order.** Between two separated
  modes the integrand is `O(n * separation / s^2)` while the integral is `O(1)`.
  Raising the Gauss-Legendre order alone leaves a truncation error that grows
  linearly in `n` — 0.73 nats at `n = 100` on `empty_valley`, i.e. a mode-weight
  TV of 0.18 for a target whose two modes are *exactly* tied. Composite
  refinement by panel doubling, with the convergence test taken relative to
  `int |S . dtheta|` rather than to `|value|` (which is exactly zero for a
  symmetric pair), removes it entirely: `1.7e-13` at `n = 100`.
* **Laplace+ needs a basin guard.** `C_b = E_{q_b}[exp(R_b)]` integrates over
  the whole space. When the branches are well separated that is the basin mass;
  when they are not, every branch's estimate converges on the *total* mass and
  the weights collapse toward uniform. Measured on a deliberately skewed
  two-mode target, unguarded Laplace+ is **worse** than plain Laplace at small
  `n`: on that target at `n = 2`, plain Laplace gives weight TV 0.026 and
  unguarded Laplace+ gives 0.052. Restricting the estimator to points whose path
  from the mode descends monotonically — a free test on scores already being
  integrated — gives 0.0009 instead, and is a no-op once the modes separate.
  The same effect shows in the gate table's `TV (Laplace+, no guard)` column:
  0.010 unguarded against 0.0008 guarded on `symmetric` at `n = 1`.

### 3.2 The headline comparison

Oracle row scores throughout, so this compares composition rules and inference
procedures, not score networks. Full tables in `artifacts/TABLES.md`; the
pattern at `n = 100`:

* ModeTree-JAC reduces the Wasserstein-1 distance to the exact tall posterior by
  **one to three orders of magnitude** relative to `gauss_jacobian` reverse
  diffusion and to F-NPSE annealed Langevin.
* Mode-weight TV goes from ~0.3 (both baselines on `map_vs_mass`) to `< 1e-4`.
* Missing posterior mass is zero on every 1-D regime tested.
* `uncorrected` diverges outright at large `n` on the asymmetric targets.

The ModeTree row is reported twice: `W1` from 2000 draws (like-for-like with the
samplers) and `W1 analytic` from the returned Gaussian mixture. The sampled
number has a Monte-Carlo floor of about `sd / sqrt(2000) ~ 0.045`, which at
`n >= 8` is *larger* than the method's actual error — the analytic column is the
one that says what the method achieves.

### 3.3 Where the errors come from

The error ladder (section 11 of the brief) is implemented as
`modetree_known` / `modetree` / the perturbed-score study:

| rung | isolates | result |
|---|---|---|
| known modes + oracle score | energy integration, Laplace, Laplace+ | machine precision; TV `< 1e-3` for `n >= 8` |
| oracle score + discovery | mode discovery | identical on every 1-D regime; the only 1-D discovery failure is `map_vs_mass` at `n = 1`, where the second mode is genuinely shallow |
| perturbed row scores | network bias | see below |

Injected row-score error (`artifacts/score_error_scaling.json`), fitted
`error ~ n^alpha`:

| shape | alpha | e_MAP at n=100 (bias 0.01) | weight TV at n=100 |
|---|---|---|---|
| systematic (fixed direction) | **+1.000** | 0.010 | **0.367** |
| zero-mean i.i.d. per row | **+0.492** | 2.0e-4 | 0.019 |
| systematic state-dependent | +1.000 | 0.0097 | 0.000 |

This is the single most consequential number in the study. A systematic
per-observation score bias accumulates exactly as `O(n)`, and its effect on the
**MAP** is benign — the error stays of order the bias in parameter units, which
is the behaviour the `MultiObsSampler` docstring already describes. Its effect
on **mode weights** is not: a 0.01 bias produces a weight TV of 0.37 at
`n = 100`, because a mode weight depends on the log-density *difference* between
modes, and that difference accumulates linearly while the posterior contracts.
Zero-mean error behaves as `sqrt(n)` and is comparatively harmless.

The practical consequence: **at large `n`, ModeTree-JAC's mode weights are
limited by the network's systematic bias, not by anything in the reconstruction
chain.** Mode *locations* and the MAP are far more robust.

### 3.4 Mode discovery, and what is load-bearing

`artifacts/experiment_2d.json` runs each 2-D regime with both mechanisms, with
sentinels only, and with curvature spawning only.

* **Sentinel probes are necessary; curvature spawning alone is not sufficient.**
  In two dimensions, curvature-only discovery fails completely on the
  four-mode targets — the softest-direction probes cannot reach corners that a
  single eigendirection does not point at.
* The `remote_small` regime (a 10% mode that no bifurcation of the dominant mode
  reaches) is found only with sentinels, which is exactly what section 15 was
  designed to test.
* In one dimension the two mechanisms are complementary: `symmetric` and
  `empty_valley` bifurcate and are found by curvature; `map_vs_mass` and
  `narrow_broad` never bifurcate (the continuation slides into one basin) and
  are found only by sentinels.

Three implementation facts turned out to decide whether discovery works at all,
and are recorded as comments at the point of use:

1. The probe distance must come from the branch's **pre-bifurcation** width. The
   obvious `1/sqrt(|lambda_min|)` shrinks as the split deepens, so every probe
   falls back into the saddle. With that choice the symmetric benchmark ends
   with *zero* branches at `n = 100`.
2. Probe acceptance must be a precision-weighted residual
   `sqrt(s^T P^-1 s)`, not `||S||`. At `n = 100` the curvature is several
   hundred, so a root located to `1e-4` in position still shows `||S|| ~ 1e-2`;
   a fixed `||S|| < 1e-4` test rejects genuine modes systematically.
3. Probe results must be collapsed **among themselves** before reaching the
   branch list, and the mode-equivalence metric must be the spectral absolute
   value of the precision (the raw quadratic form is indefinite at a saddle, so
   every candidate looks like a duplicate of the saddle).

### 3.5 Section 13/14 special tests

* **MAP vs mode mass.** `map_vs_mass` is constructed so the higher peak and the
  heavier mode are different branches at *every* `n` (peak at `+mu`, 66% of the
  mass at `-mu`). ModeTree reports them separately and correctly; a test
  asserts `map_index != mass_index`.
* **Empty valley.** With two modes separated by an essentially zero-density
  region, ModeTree places no branch in the valley (asserted in the test suite:
  every branch satisfies `|g| > 4`), and recovers the exactly-tied energies to
  `1.7e-13` at `n = 100`.
* **Very close mode heights.** `nearly_tied` keeps the two modes within a few
  `1e-2` of each other at all `n`; the reconstructed energy gap error stays
  below `2.3e-13`, so the evidence auditor never has to fire. The multi-path
  disagreement and cycle residuals are reported regardless, and are `~1e-14`
  for the oracle field — which is the point: they are the quantity that would
  become informative with a learned, non-conservative score.
* **Mode disappearance with `n`.** The `vanishing` and `narrow_broad` regimes
  have a fixed per-observation tilt, so one mode dies exponentially. ModeTree
  keeps it while it has mass, lets its weight shrink, and the branch count
  follows the truth rather than a constant.

### 3.6 Benchmark construction (a result in its own right)

For a product of `n` identical factors the tall log-height gap between two modes
is `n` times the per-factor gap. **Any** fixed per-observation asymmetry
therefore kills all but one mode exponentially — at `n = 100`, a 0.62/0.38
component weight leaves the second mode with `6e-22` of the mass. A benchmark
whose mode weights stay non-degenerate along the `n` ladder must calibrate the
per-observation tilt as `O(1/n)`, and in `d > 1` must calibrate the **volume**
term `-1/2 log|S_k|` too, since that is multiplied by `n` as well. Both
calibrations are implemented (`tilted_two_mode_1d`,
`calibrate_component_weights`) and both kinds of regime are kept: the calibrated
ones probe weight accuracy at high `n`, the fixed-tilt ones probe mode
disappearance.

## 4. Answers to the ten research questions

**Q1 — can curvature continuation + sparse sentinels recover all meaningful
modes?** Yes on every benchmark here, but *only with sentinels*. Curvature
spawning alone fails on every target whose second mode is born by a saddle-node
rather than a pitchfork, which includes all the 2-D four-mode targets and the
1-D `map_vs_mass` / `narrow_broad` regimes.

**Q2 — can score-line integration + cycle consistency recover relative mode
heights?** Yes, to `< 2.3e-13` on the oracle field at `n = 100` — but only with
panel-refined composite quadrature. With order-only refinement the error grows
linearly in `n` and reaches 0.73 nats.

**Q3 — does structured Laplace recover relative mode masses as `n` grows?**
Yes, and it *improves* with `n`: weight TV falls from ~0.02 at `n = 1` to
`< 1e-3` by `n = 8` and `< 1e-4` by `n = 32`, because the modes narrow relative
to their separation.

**Q4 — does Laplace+ materially improve on ordinary Laplace?** At small `n`,
substantially (TV 0.043 → 0.0005 on a skewed target at `n = 1`). At large `n`
the improvement is real but immaterial, because plain Laplace is already at
`1e-4`. Its ESS never collapsed (minimum observed fraction 0.87).

**Q5 — at what `n` does Laplace+ become unnecessary?** Around `n = 8-32` for
these targets. Beyond `n ~ 32` the two agree to better than the Monte-Carlo
resolution of any downstream use.

**Q6 — how does learned score bias accumulate with `n`?** `alpha = 1.000` for
systematic error, `alpha = 0.492` for zero-mean error, exactly as the algebra
predicts. The damage lands on mode weights, not on the MAP. See 3.3.

**Q7 — does ModeTree-JAC improve with `n`?** Every component of the
reconstruction improves with `n` (the modes narrow, Laplace gets better, the
energies stay exact). With a *learned* score the systematic-bias term of Q6
eventually dominates the weights; on present evidence the crossover for mode
weights is at a bias of order `0.005-0.01` in score units.

**Q8 — discovery or weighting as the remaining error source?** With oracle
scores, neither: both are at machine precision once the three implementation
facts of 3.4 are right. With a biased score, **weighting** — by a wide margin.

**Q9 — how many branches?** The true mode count, plus transient saddle branches
that are pruned. `B <= 4` on every benchmark here; the branch count does not
grow with `n` (failure condition 6 is not triggered).

**Q10 — is it faster than F-NPSE?** See the runtime table in
`artifacts/TABLES.md`. ModeTree is *not* uniformly faster in wall clock on
these problems, and the reason is worth stating precisely rather than hiding:
the oracle row score here is a handful of float64 kernels, so the cost is
dominated by Python-level branch bookkeeping rather than by score evaluation,
which inverts the ratio that matters in production. The *architecture-independent*
number is the composed-field evaluation count, and there ModeTree uses roughly
the same order as a 200-step reverse diffusion and fewer than F-NPSE's
1000 (100 levels × 10 Langevin steps) — see 5.2.

## 5. Honest accounting

### 5.1 What is not done

* **The learned-network rung (section 27) is not run.** Everything is built and
  tested against *oracle* row scores. Running the third experiment requires a
  trained COMPASS checkpoint on a multimodal tall-data model; the adapters it
  needs are the ones `TECHNICAL_NOTE.md` section 4.1 identifies
  (`_raw_row_scores`, `_row_score_jacobian`), and `row_jacobian_factor` is
  already written to take a network Jacobian unchanged. Until that is run, no
  claim here about network error is empirical except the injected-error study
  of 3.3, which is a controlled proxy and is labelled as one.
* **SBC is run at one `(case, n)` only** (figure 6), on a synthetic bimodal
  target, and it is the weakest measurement in the report: 200 datasets and
  200 draws each give rank-histogram resolution of roughly ±0.05.
* **Laplace+ for hierarchical models** is not implemented; it is defined on the
  global block, and the hierarchical path uses ordinary structured Laplace. The
  profiled-composer route is sketched in `laplace._global_score` but not built.
* **Milestone O (the evidence auditor)** is implemented only as the diagnostics
  it needs — per-pair uncertainty `sigma_ab`, multi-path disagreement, cycle
  residuals are all computed and stored — but the *escalation* (more quadrature,
  more paths, PF-ODE log density) never triggers on the oracle field because the
  disagreement is at machine precision. It is the right piece to build with the
  learned network, not before.
* **Milestone M4 (low-rank JAC)** was deliberately not built: profiling does not
  show Jacobian cost dominating at these dimensions, and the brief says not to
  add the machinery unless it does.

### 5.2 Runtime, plainly

The wall-clock comparison on this benchmark is not a fair proxy for production.
With an oracle score, one composed-field evaluation is microseconds, so
ModeTree's per-branch Python loop dominates and it does not beat F-NPSE in
seconds. With a transformer score network the per-evaluation cost rises by
three to four orders of magnitude and the *evaluation count* becomes the whole
story. Both numbers are in the tables; the evaluation counts are the ones that
transfer. The target `T_ModeTree < 0.5 T_FNPSE` is therefore **not verified**,
and cannot be verified without the network rung.

## 6. Recommendation

**Adopt the reconstruction half now; keep the discovery half behind a flag until
the learned-network rung is run.**

Concretely:

1. The **structured-Laplace + score-line-integration reconstruction** (Milestones
   B–G) is sound, exact to machine precision on every oracle benchmark, and
   improves with `n`. It is worth landing in COMPASS as a post-processing step
   that turns any set of refined modes into a weighted posterior, independently
   of where the modes came from. `newton_map_estimate` already produces exactly
   the arrowhead quantities it needs.
2. The **prior-object interface** (`compass.priors`) should land unconditionally.
   It is backward-compatible, small, and removes a real limitation: the
   composition subtracts `(n-1)` prior scores, so a Gaussian-only prior is an
   `n`-fold amplified modelling error on any multimodal problem.
3. **ModeTree discovery** works but is the part with the most moving parts and
   the most tuning-sensitive behaviour (three of its defaults were silently
   wrong in ways that produced zero or one branch rather than an error). It
   should ship as `correction="mode_tree_jac"` with `return_diagnostics=True`
   encouraged, and should not become the default until it has been run against
   a real COMPASS checkpoint.
4. The **next experiment** is the one thing that would change this
   recommendation: run the ladder in 3.3 with real network scores, measure the
   actual systematic bias of a trained COMPASS model in score units, and compare
   it against the `0.005-0.01` threshold at which mode weights start to degrade.
   If the measured bias is below it, ModeTree-JAC is ready to be a main COMPASS
   inference method for multimodal tall data. If it is above it, the correct
   response is better training, not a different composition rule — because
   3.3 shows the composition mathematics is not what is failing.

The scientific priority order in the brief is
`posterior correctness > MAP accuracy > mode-mass accuracy > calibration >
runtime`. On the first three, with exact scores, ModeTree-JAC is better than
`gauss_jacobian` and F-NPSE by orders of magnitude and has no regime here where
it is worse. On calibration the evidence is thin. On runtime the honest answer
is "not established in the units that matter".
